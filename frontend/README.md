# COD Guard frontend

Shop web app and buyer confirmation page. React 19 + TypeScript on Vite.

| Concern      | Library                                                                                                                                                                                                                                         |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Components   | [shadcn/ui](https://ui.shadcn.com) and ReUI's frame (`src/components/ui/`); [ReUI](https://reui.io) (`src/components/reui/`: data grid, filters, timeline, stepper, badge, alert, icon tile, file type, time picker, number field, phone input) |
| Page blocks  | ReUI blocks adapted to COD Guard (`src/components/blocks/`, see "Screens")                                                                                                                                                                      |
| Styling      | Tailwind CSS v4, theme tokens in `src/index.css`; charts with recharts through the shadcn chart component                                                                                                                                       |
| Routing      | TanStack Router, file-based (`src/routes/`, generates `src/routeTree.gen.ts`)                                                                                                                                                                   |
| Server state | TanStack Query, with query options generated by Hey API                                                                                                                                                                                         |
| API client   | [Hey API](https://heyapi.dev) generated from `api/openapi.yaml` into `src/api/gen/`                                                                                                                                                             |
| Mock API     | In-browser, stateful (`src/mocks/`), for endpoints the backend has not built yet                                                                                                                                                                |
| Client state | Zustand (`src/stores/`): auth token, theme, onboarding, mocked endpoints                                                                                                                                                                        |
| Tests        | Vitest + Testing Library                                                                                                                                                                                                                        |

## Commands

Run from `frontend/`. Needs Node.js 20+ and pnpm (`corepack enable` picks up the version pinned in `package.json`). From the repo root, `make dev` starts the backend and this app together.

| Task                                 | Command                                        |
| ------------------------------------ | ---------------------------------------------- |
| Install                              | `pnpm install`                                 |
| Dev server                           | `pnpm dev` (http://localhost:5173)             |
| Dev server without a backend         | `VITE_API_MOCK=all pnpm dev`                   |
| Prism mock (fixed contract examples) | `pnpm mock` (:4010; optional)                  |
| Regenerate the API client            | `pnpm generate:api`                            |
| Lint                                 | `pnpm lint` (oxlint)                           |
| Format                               | `pnpm format` / `pnpm format:check` (Prettier) |
| Type check                           | `pnpm typecheck`                               |
| Tests                                | `pnpm test`                                    |
| Production build                     | `pnpm build` (output in `dist/`)               |

## Talking to the API

The app calls `/api/...` on its own origin. In development Vite proxies `/api` to the backend on
port 8080 (`API_PROXY_TARGET` overrides it). The client is generated, never edited by hand: after
the backend re-exports `api/openapi.yaml`, run `pnpm generate:api` and commit `src/api/gen/`. CI
fails when the generated client is out of date.

```tsx
import { useQuery } from '@tanstack/react-query'
import { listOrdersOptions } from '@/api/gen/@tanstack/react-query.gen'

const { data, error } = useQuery(listOrdersOptions({ query: { tier: ['high'], limit: 50 } }))
```

Base URL, auth and the mock are set in `src/api/client-config.ts`. The bearer token comes from
the Zustand auth store, and a 401 signs the user out. Errors are thrown as the parsed
`ProblemDetail`; `src/lib/api.ts` turns them into English messages.

### Mock API (`src/mocks/`)

Endpoints that are in the contract but not built yet answer `501 not_implemented`. The client's
`fetch` (`src/mocks/fetch.ts`) then answers from an in-browser mock instead, so every screen works
before its backend exists and switches to the backend as soon as the endpoint is built.

| `VITE_API_MOCK`      | Behaviour                                                                    |
| -------------------- | ---------------------------------------------------------------------------- |
| `fallback` (default) | Call the backend; replace only 501 answers with the mock                     |
| `all`                | Answer every request from the mock; no backend needed (`make dev` uses this) |
| `off`                | Backend only                                                                 |

- `seed.ts` generates a deterministic shop: about 80 orders across every order state, with
  scores, at most 3 reasons each tied to a signal on the order, decisions, contacts, AI calls and
  timelines. Names are generated and phones use the invalid `+84000…` prefix.
- `db.ts` keeps state for the session and follows the domain rules: overrides need a reason and
  are one of the backend's four (ship now, require deposit, hold for review, cancel), a
  confirmed or shipped order is never contacted again, "I didn't order this" blocks the phone, two call
  attempts at most. The inbox filters, searches and pages like the backend.
- The header shows a "Sample data" badge whenever data comes from the mock, listing which
  endpoints. Simulated Zalo ZNS / SMS and the browser phone are labelled "mock".
- Demo login: `admin@gmail.com` / `admin12345` (same as the backend's `.env.example`).

## Adding components

- The style is `base-nova` (`components.json`): components are built on Base UI
  (`@base-ui/react`), not Radix.
- shadcn: `pnpm dlx shadcn@latest add <name>`.
- ReUI: `components.json` points the `@reui` registry at a local mirror on port 4000. Start it
  with `reui serve`, then `REGISTRY_URL=http://localhost:4000/r pnpm dlx shadcn@latest add @reui/<name> --yes`
  (the CLI adds `/styles/base-nova` itself). Without the mirror, change the `@reui` entry to
  `https://reui.io/r/{style}/{name}.json`.
- `src/components/ui/` holds every shadcn primitive ReUI depends on (`reui primitives` lists
  them), so ReUI components and blocks install without pulling in new base components. The one
  exception is `toast`: nothing uses it, toasts go through sonner.
- Files under `src/components/ui/` and `src/components/reui/` come from the registries. Prefer
  reinstalling over editing them; ReUI files are skipped by oxlint and Prettier.
- Blocks under `src/components/blocks/` are installed once and then adapted (real data, routes,
  English copy), so they are linted and formatted like our own code. Do not reinstall them over
  the adapted files.

### Base UI in our code

Most Radix habits still type-check under Base UI but do nothing at run time. Use these instead:

- `render={<Element />}` instead of `asChild`; the children go on the component, not the element.
- A link that looks like a button is a `<Link className={buttonVariants(…)}>`. `<Button render={<Link />}>`
  turns it into `role="button"`.
- Menu items take `onClick`; `onSelect` is the DOM text-selection event and never fires. Keep a
  menu open on click with `closeOnClick={false}`.
- `Select` needs `items` (value → label) or `SelectValue` shows the raw value. `onValueChange`
  can pass `null`.
- `ToggleGroup` takes `multiple` instead of `type`; `TooltipProvider` takes `delay` instead of
  `delayDuration`.
- State attributes are `data-checked`, `data-open`, `data-active`… instead of `data-[state=…]`.

## Deploy

Every push to `main` that passes CI builds `Dockerfile` (the Vite build served by nginx) and
deploys it to the Cloud Run service `codguard-web` in `asia-southeast1`, right after the backend.
nginx forwards `/api/...` to `codguard-api` (the `API_ORIGIN` variable, see `nginx.conf.template`),
so the app and the API share one origin and the backend needs no CORS. The app URL is in the
summary of the CI run.

The image keeps the build-time defaults: same-origin API, and the mock only for endpoints that
still answer 501. To run it against a local backend:

```bash
docker build -t codguard-web .
docker run --rm -p 3000:8080 --add-host host.docker.internal:host-gateway \
  -e API_ORIGIN=http://host.docker.internal:8080 codguard-web
```
